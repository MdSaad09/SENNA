# Curriculum ledger

The teacher agent reads this before writing any lesson and appends to it afterwards.
A concept listed here is considered taught: later lessons reference it with one line,
they do not re-explain it.

| Concept | First taught in | One-line definition |
|---|---|---|
| Lockfile (intent vs resolution) | F00 | Human-edited intent file (`requirements.in`, `package.json`) compiled into an exact, machine-generated pin of the whole dependency tree. |
| Pin what breaks, float what does not | F00 | 5.9.1 pin policy: exact-pin only known-breaking pairings (SB3/sb3-contrib, React 18/R3F 8); range-float the rest. |
| Environment markers | F00 | Per-platform conditions on lockfile lines (`; sys_platform == 'linux'`) so one universal lock serves mac and linux. |
| Resolver backtracking | F00 | A dependency solver walking back through old releases to satisfy constraints; fixed by adding a floor on the misbehaving package, not its neighbours. |
| docker compose services and healthchecks | F00 | Named containers on a private network; `depends_on: service_healthy` gates startup on a real readiness probe, not container start. |
| The browser boundary (F-27) | F00 | Docker hostnames are valid server-side only; anything reaching the browser (`VITE_*`) must be a browser-reachable URL or path. |
| Anonymous volume mask | F00 | A bare container path in `volumes:` (`/app/node_modules`) that shadows part of a bind mount so host-native binaries stay out of the container. |
| Tests as forcing functions | F00 | Writing the failing test first so its failure list is the work order (the anchor test drove the 15-file spec split). |
| CI on push (GitHub Actions) | F00 | A clean machine re-runs lint, pytest and vitest from the lockfiles on every push; disagreements with your laptop mean hidden local state. |
| pytest pythonpath parity | F00 | `pythonpath = ["."]` in pyproject makes bare `pytest` (CI) import like `python -m pytest` (local). |
| Spec anchors | F00 | The `Spec anchors:` line in each feature spec, machine-resolved to files on disk by `scripts/check_spec_anchors.py`. |
| Provenance comments | F00 | The interpretability contract applied to constants: every pin/number carries a comment naming its source (spec row, fit, or explicit choice). |
| pandas DataFrames and NaT/NaN | F01 | In-memory tables with typed columns; NaN/NaT mark missing numbers/times, are contagious, and need `pd.isna()`, not `==`. |
| SQLAlchemy ORM vs Core | F01 | ORM classes declare tables once (`Mapped`/`mapped_column`); Core statements (`insert`/`select`/`delete`) do bulk work without per-row objects. |
| async/await and asyncpg | F01 | Coroutines yield at `await` to an event loop; asyncpg only works this way, so DB code is async end to end with one `asyncio.run()` at the top. |
| Alembic migrations | F01 | Ordered, reversible schema-change scripts (`alembic upgrade head`); unlike `create_all`, they can alter populated tables and CI's `alembic check` catches drift. |
| Transactions, unique constraints, upserts | F01 | `engine.begin()` commits all-or-nothing; unique constraints refuse duplicates; `ON CONFLICT` turns insert-or-update into one atomic statement. |
| Token-bucket rate limiting | F01 | A bucket of `burst` tokens refilling at `rate`/s; each request spends one, so bursts pass but the long-run rate is capped (AR-15/E-12). |
| Fixtures and injectable clocks | F01 | pytest injects named builders by argument; passing `clock`/`sleep` as functions lets tests run on virtual time — no test ever really sleeps. |
| Delete-and-reload vs upsert idempotency | F01 | Keyless tables can't upsert; deleting a session's rows and reinserting inside one transaction makes any rerun a clean no-op. |
| Checkpointed resumable batch jobs | F01 | One state row per work unit, flipped to `loaded` in the same commit as the data; reruns skip terminal states, so a killed run loses nothing (E-12). |
| Flagged superset storage | F01 | Store every raw row plus derived flags (`is_green`, `lap_time_imputed`); fits filter at query time, so no cleaning decision is irreversible (E-09/5.3.4). |
| 404 as zero rows | F01 | Some APIs 404 an empty query; where "no rows" is a legal answer the client translates that status to `[]` per endpoint — absence is data, errors stay errors (F-14). |
| OLS with fixed effects | F02 | Least squares on a design matrix with drop-one 0/1 dummy columns per category level, so slopes are estimated within driver/session/compound. |
| Collinearity, VIF and condition number | F02 | Near-linear dependence between regressors; VIF = 1/(1−R²) of one column on the rest, condition number the same worry matrix-wide — both reported per fit (E-10). |
| Identifiability vs noise | F02 | Noise shrinks with data; unidentifiable means the data cannot distinguish two explanations — report what is pinned down and flag the rest (`identified: false`). |
| Partial residuals | F02 | Raw residuals plus one term's fitted contribution added back: "the data with everything except this term removed" — the degradation fit's input. |
| Inverse-variance pooling | F02 | Combine estimates weighted by 1/SE²; minimum variance for unbiased inputs, which is why confounded (not merely noisy) fits must be excluded first. |
| Wilson score interval | F02 | A proportion confidence band that stays usable at 0-of-n and small n, unlike the normal approximation's zero-width collapse at the boundaries. |
| Per-race probability to per-lap hazard | F02 | λ = −ln(1−p)/laps inverts "chance of ≥1 event in L laps of constant hazard"; saturated counts shrink to n/(n+1) before the log (5.5.3). |
| scipy curve_fit with bounds | F02 | Nonlinear least squares for models like a·age^b; bounds keep coefficients physical and p0 seeds the local optimiser. |
| KMeans and silhouette | F02 | Distance-based clustering on standardised features; silhouette scores pick k, and a fixed seed keeps transfer donors stable across reruns (T5). |
| Trapezoidal integration on irregular timestamps | F02 | Integrate with actual dt per sample pair, `dt·(y₁+y₂)/2`, never a nominal rate; stop at every trace break so dropouts donate nothing (AR-16/F-13). |
| The YAML 1.1 float trap | F02 | `repr(7e-06)` has no dot, so `safe_load` returns a string; scientific notation must be written `7.0e-06` to load back as a float. |
| Byte-deterministic artifacts | F02 | Same data in, identical bytes out: total ORDER BY on every query, sorted keys in the writer, and a data watermark instead of a clock. |
| Point-mass longitudinal model (effective car) | F03 | Car as mass under effective power and drag `m·a = P/v − beta·v²`, both fitted from telemetry so they absorb every unsourced physical constant (T1, 5.4). |
| RK4 ODE integration | F03 | Fourth-order Runge-Kutta solving the point-mass trajectory over distance; four gradient samples per step, error ~step⁵, validated against the flat-out closed form. |
| Frozen train/validation split and data leakage | F03 | Calibrate on 2026 rounds 1–6, validate on 7+ (E-14); leakage is any path by which held-out data reaches a fit, blocked here in three independent layers. |
| Distribution distances (KS, EMD) | F03 | KS is the max gap between two CDFs, EMD the work to reshape one histogram into another (laps for stints); the 5.4.1 sim-to-real metrics. |
| Logistic regression by Newton-Raphson | F03 | Maximum-likelihood fit of a probability model `P(pass) = sigmoid(design·beta)`, iterated to convergence by hand — T7's overtaking model. |
| Derived quantity vs noisy regression | F03 | Computing `c_lc` as an exact slope off the calibrated model (sweep lift depths) instead of regressing confounded race laps. |
| Seeded Monte Carlo with stream spawning | F03 | `SeedSequence(seed).spawn(n)` gives each simulated race an independent reproducible RNG, so validation figures regenerate byte-identically (5.5.5). |
| GLTF / GLB mesh (positions + indices) | F04 | A 3D model as two lists — a flat vertex-position buffer and integer triangle indices into it; GLB packs the glTF JSON and buffer into one binary file the frontend loads (5.10.1). |
| Arc-length resampling | F04 | Re-dropping points at uniform distance along a path (every 2 m) instead of uniform time, so corners and straights get equal point density for smoothing and curvature. |
| Savitzky-Golay filter | F04 | Sliding-window smoothing that fits a low-order polynomial per window and takes its centre value, keeping corner shape while killing GPS noise; Z smoothed harder than X/Y. |
| Frenet vs rotation-minimising frames | F04 | Frenet's normal flips 180° at inflections/hairpins; RMF carries a sideways vector along the curve by parallel transport (double reflection) with minimal rotation, so the ribbon never twists (E-17). |
| Parallel transport and holonomy | F04 | Transport carries a frame forward with least turn; on a closed loop the residual twist (holonomy angle) is measured and spread over all stations so the frame is periodic and the seam is clean. |
| Menger curvature / radius of curvature | F04 | Local radius from three consecutive points, r = (a·b·c)/(4·area); inf on straights, small in hairpins — the ribbon half-width is clamped below it so tight corners cannot fold (5.10.1 item 4). |
| Segment-intersection orientation test | F04 | Two segments cross only if each straddles the other, tested by the sign of the triangle-orientation cross product; shared endpoints give zero and never count, so the loop seam is legal (E-17). |
| Stylised vs sourced provenance (visual data, F-12) | F04 | The anti-black-box rule for pixels: numbers that only change how the track looks (elevation, camber, width) are flagged `stylised` in config and metadata, so the UI never shows decoration as data. |
| Gymnasium environment (reset/step loop) | F05 | An RL env exposing `reset()` and `step(action)` that returns observation, reward, terminated and info; the agent sees only observations and rewards and learns the mapping — SB3 trains against this contract (5.5). |
| MultiDiscrete action space | F05 | Two independent discrete choices picked together, `MultiDiscrete([6, 4])` — a pit head and a mode head — so the structure of "pit and mode are separate decisions" is visible to the agent (5.5). |
| Action masking (legal by construction, F-16) | F05 | A boolean vector per head zeroing illegal actions before sampling, plus physics clipping of continuous limits; together 100% compliance by architecture, with reason codes, not a reward penalty. |
| Scale-bounded observation | F05 | The 32-dim ego vector (5.5.1), every slot named and pre-clipped to about [-1, 1] at encode time, so a served model degrades gracefully if VecNormalize statistics drift. |
| Potential-based reward shaping (telescoping, F-15) | F05 | Shaping `F = gamma x Phi(s') - Phi(s)` with `Phi = -0.1 x position`; provably policy-invariant and sums to zero over any position cycle, killing the oscillation exploit that broke v2. |
| Struct of arrays / hot-loop rule | F05 | Race state as one numpy array per attribute across all 22 cars, not per-car objects, so the field advances in vectorised numpy with nothing pandas-shaped reachable from `step()` (5.6.2). |
| Era switch (A-10) | F05 | One `build_scenario` recipe reading either physics_2026 (synthetic energy integrals) or physics_2024 (MGU-K budget), so the same env code runs both the 2026 race and the 2024 counterfactual. |
| Rival archetypes and train/test split (E-06) | F06 | Three named rule sets (undercutter, tyre_saver, opportunist) whose thresholds are drawn per race from bands, with a disjoint harder `test` band held out for eval so a good score means robustness not memorisation. |
| Degeneracy avoidance / per-car Bernoulli response (E-06) | F06 | The safety-car response is an independent weighted coin flip per car against a per-race probability, so the field's answer to a neutralisation is a distribution the agent cannot memorise as one pattern. |
| Deterministic twin / EventTrace (A-05, M3) | F06 | A full recording of every random event a race applied, replayed with noise zeroed so events freeze while the ego strategy varies — the honest fix for "same seed is not same race" and the surface oracle regret measures against. |
| Strategy-policy interface and scripted baselines (A-07) | F06 | One `reset`/`act` contract (obs, info, mask in; MultiDiscrete action out) shared by the engineer heuristic, the replayed-real strategy, random-legal and the agent, so all are scored by one rollout harness. |
| DP oracle and oracle regret (A-05, M3) | F06 | A two-stage search — exact per-compound stint tables rank all 1-3 stop plans, top finalists get full twin rolls restoring traffic and the pit FIFO — giving the best-possible race ceiling; its assumptions are published so an easy oracle can't flatter the agent. |
| Throughput benchmark (5.6.2) | F06 | Env steps/s across N SubprocVecEnv workers with the mask fetch on the clock — the one number that prices the training plan; below ~300/s, profile the env before trusting any budget. |
| Stage A/B competence gates and solo reference (5.7) | F06 | Stage A checks the agent against the best 1-3 stop plan on an empty green race (`solo_reference`), Stage B against the baselines in a real field; F06 builds both reference points, F07 runs the gates. |
| PPO / MaskablePPO (5.6.1, F-16) | F07 | Clipped policy-gradient RL — collect rollouts, advantage-weighted nudge, clipped per batch — with action masks applied inside the distribution; sb3-contrib fetches `action_masks()` through the vec stack, so no wrapper is needed. |
| VecNormalize observation statistics (5.6.1) | F07 | A vec-env wrapper keeping running mean/variance per obs slot and feeding the net z-scores; obs only, never the hand-scaled reward — and the statistics are learned state the model is meaningless without. |
| Checkpoint triplet (F-23) | F07 | Weights + vecnormalize.pkl + manifest saved atomically as one unit, both artifacts sha256-stamped into the manifest, so a served model can prove which statistics it was frozen with — the guard against the silent wrong-inputs deployment bug. |
| Gate decisions as pure functions, budgets as ceilings (F-21, R-12) | F07 | Stage advancement decided by pure functions of eval histories (plateau best-of-window, one-sided time bar, paired finish-ahead, stagnation clock) whose signatures have no budget input; a ceiling hit logs `budget_stop`, never a transition. |
| Matched-gamma telescoping and the conscious mismatch (F-15, 5.5.4) | F07 | Potential-based shaping is exactly policy-invariant only when the training gamma equals the shaping gamma; SENNA trains at 0.997 against shaping gamma 1.0 as a documented choice with a quantified ~0.0003/lap residual and matched-gamma F08 ablations. |
| Ablation study and the matched control (5.6.3, F-22) | F08 | Change one component per arm and measure against a control that changes nothing; SENNA runs all four arms as Stage C from scratch at 4M with the global 8M lr horizon kept, so arms differ from the control on exactly one axis and from the headline only in the curriculum. |
| Reward hacking and the faithful strawman (F-15, F-17) | F08 | A policy maximising the written reward, not the intent (v2's +1.0/−0.8 position pair pays +0.2 per oscillation); the ablation rebuilds v2's reward with its pathologies pinned by test, unquoted values tagged `reconstructed`. |
| Penalised compliance vs masking (5.6.3 row 2, F-16, E-01) | F08 | The `constraints="penalty"` variant reports all actions legal, executes illegal requests and fines them −8.0 under the true mask's reason codes — while physics clipping never relaxes, so only discrete legality changes architecture. |
| Data limit vs sporting rule (F08 mask guard) | F08 | A slick with no degradation fit is masked structurally with the `UNFITTED_COMPOUND` reason in every constraints mode — missing physics has no price, so no fine can buy it out, unlike sporting rules a penalty arm may breach and pay for. |
| Config overlays and the write-ahead run ledger | F08 | Each arm trains from a derived copy of configs/ whose bytes make its fingerprint self-describing, and models/runs.json gets its row (status "running") before the first step, so interrupted runs are visible and restarts honest. |
| Cross-seed selection with verified promotion (5.7, F08) | F08 | Best validation points across seeds, ties to the earlier step then the lower seed; promotion re-verifies the chosen best/ manifest against the gate log before atomically copying to models/headline — check the claim, never trust the coupling. |
| SHAP values and the background set (5.8.1) | F09 | A feature's average marginal contribution to the chosen action's logit under the Shapley axioms, always measured *against* a stated background distribution — SENNA's is 1,024 stratified states, documented as an artifact because the attributions depend on it. |
| Surrogate distillation and the fidelity gate (F-25, A-04) | F09 | TreeSHAP only works on trees and KernelExplainer on the MLP was priced at ~1e9 forward passes, so a gradient-boosted tree is fitted to imitate the policy; top-1 agreement on held-out episodes is printed on every card and `FidelityGateError` refuses to ship below 0.90. |
| Weighted row expansion for soft targets | F09 | Fitting probability targets with a stock `multi:softprob` objective by emitting one row per action with weight equal to its target probability — weighted cross-entropy over the expansion equals the soft-target cross-entropy, no custom gradients. |
| Masked fidelity (measured as the card consumes it) | F09 | Fidelity scored after applying the recorded mask to the surrogate's distribution and renormalising, with mean KL(policy ‖ surrogate) reported alongside top-1 because a binary agreement rate cannot distinguish 0.51-vs-0.49 from 0.99-vs-0.01. |
| Counterfactual flip probe (5.8.2) | F09 | One feature swept across its physical range against the true policy with the mask rebuilt at every point, walking outward from the recorded value so the reported crossing is the nearest one rather than the range floor. |
| Rank-correlation cross-check (A-04) | F09 | GradientExplainer attributions on the real network for a 500-decision sample, Spearman-correlated with the surrogate's TreeSHAP; ranks rather than magnitudes because tree margins and network logits are not on a common scale. |
| Episode-level holdout for a reported metric (E-14 applied) | F09 | Splitting the fidelity holdout by whole race rather than by state, because consecutive laps are near-duplicates and a state-level split leaks them across the boundary and inflates the badge in the one direction that matters. |
| FastAPI and event-loop ownership (F-26) | F10 | Every handler and every WebSocket share one asyncio event loop, so nothing blocking may run in the API process — simulation goes to the worker, file IO to `run_in_threadpool`, and /health must answer mid-race. |
| Pydantic response models as the contract (5.9.2) | F10 | The API's shapes declared once as validated classes ("change the spec before changing a shape"); `extra="forbid"` on requests so a typo'd field is a 422, not a silently dry race. |
| RQ job queue and worker topology (5.9.3, F-26) | F10 | Jobs are a function path plus args in Redis, drained by a separate process from the same Docker image; production runs SimpleWorker because the default forking worker discarded the load-once model cache per job — invisible under tests' in-process SimpleWorker. |
| Redis as queue, cache and pub/sub at once | F10 | One Redis wearing three hats named in configs/serving.yaml: RQ's job lists, the E-15 result cache (SET NX as an atomic claim against duplicate enqueues), and events:{run_id} pub/sub waking early WebSockets — coordination only, results live in Postgres. |
| Versioned cache keys and stale-run recovery (E-15) | F10 | `sim:{model_version}:{env_hash}:{scenario_digest}:{seed}` with version and hash read from the served manifest so a retrain cold-starts its namespace; a hit is checked against the row behind it, and a run dead past two job budgets has its key deleted rather than answering for seven days. |
| WebSocket playback clock (E-16) | F10 | The socket replays persisted lap_frames rows on an injectable timer (delay = fitted lap time / speed; 1x = one wall second per simulated second), so pause, seek, speed and reconnect are all reads and producer speed never couples to playback. |
| The two-future select loop | F10 | `asyncio.wait({receive, tick}, FIRST_COMPLETED)` races the client's next message against the frame timer; a message that changes playback cancels the in-flight tick, because at 1x waiting it out is a whole lap of wall clock. |
| Postgres advisory locks and transaction ownership | F10 | An application-defined mutex serialising concurrent migrators (both entrypoints migrate on boot); the lock SELECT's implicit transaction must be committed before alembic gets the connection, or alembic assumes caller ownership and the upgrade rolls back silently with exit 0. |
| Baked artifacts on ephemeral filesystems (F-26) | F10 | The frozen triplet, surrogate set and ribbons are COPY'd into the one serving image (precise .gitignore negations), never mounted or fetched at boot; MODEL_VERSION selects among what is baked or fails loudly at startup. |
| Operational provenance origin | F10 | The fourth config origin (decision, 22 Jul 2026) for engineering defaults — timeouts, page sizes, poll cadences — each carrying its sizing rationale, so RQ's silent 180 s default becomes an explicit, reviewable 600 s. |
| React components and the re-render rule | F11 | UI as functions re-run on state change, diffed and patched; a render costs allocation and diffing, so nothing may re-render at 60 fps — per-frame work mutates three.js objects through refs. |
| three.js scene graph and draw calls | F11 | A tree of Object3D transforms whose mesh leaves pair a geometry (vertex buffers) with a material (shader program); each visible mesh is one CPU-to-GPU draw call, the unit 5.10.3 budgets at 150. |
| @react-three/fiber (JSX scene, useFrame) | F11 | A React renderer targeting three.js: JSX declares scene structure once (and unmounting disposes it), while useFrame callbacks mutate transforms per frame — never React state. |
| react-router and the one-canvas rule (F-28) | F11 | Views are URLs in one route table; navigation unmounts the old element tree, running every cleanup, so "at most one canvas" is architectural — the shell owns none, each canvas view owns exactly one, pinned by a MutationObserver peak-count test. |
| zustand and transient subscriptions | F11 | A store outside React with three doors: hook selectors re-render on slice change, getState() reads without subscribing (the useFrame door), and subscribe(selector, cb) drives DOM writes at frame rate with zero renders. |
| react-query server state | F11 | Fetches declared as cached queries keyed by queryKey, with deduping and refetchInterval polling; staleTime: Infinity on finished-run frames encodes E-16's "stored frames never change". |
| InstancedMesh, per-instance attributes and the label atlas | F11 | One geometry drawn N times in a single call with per-instance matrix, colour and custom attributes; all 22 cars plus one atlas-textured quad mesh for sprite text is three draw calls, with frustumCulled off because the base bounding sphere knows nothing about instance spread, and the shader mirroring v because flipY is off. |
| vitest/jsdom and the WebGL test boundary | F11 | jsdom implements DOM but no WebGL, so R3F is mocked at the Canvas boundary, logic lives below it as pure lib/ functions, and what jsdom cannot see (draw calls, fps, bloom, real context loss) goes on a named runtime checklist. |
| Centreline rebuilt by arc length | F11 | The F04 GLB keeps station i's edges at vertices 2i/2i+1; midpoints rebuild the centreline, and a cumulative arc-length table with binary search gives sampleAt/tangentAt in O(log n) per car per frame, wrap included. |
| Mod-1 unwrap and Fritsch-Carlson interpolation | F11 | Per-lap s_track fractions unwrap to monotone progress via delta − round(delta) + 1 (assumes true advance in 0.5–1.5 laps); Fritsch-Carlson tangent limiting makes the cubic monotone by construction, so an interpolated car never reverses — the reason Catmull-Rom was rejected. |
| WebGL context loss (E-18) | F11 | Browsers reclaim GPU contexts under pressure; preventDefault on webglcontextlost is the contract for restoration, the DOM overlay explains the black canvas from outside it, and the dev overlay can rehearse the loss via WEBGL_lose_context. |
| Frontend provenance ring (5.1 invariant 2) | F11 | Every response passes through one fetch wrapper into a bounded ring (path, status, run/model/config ids, X-Model-Version) before the caller sees it; the backtick overlay renders the ring, so any on-screen number traces to its response. |
| Seeded property loops | F11 | Property-style invariants as plain loops over a mulberry32-seeded generator with the seed printed in every assertion, trading a fast-check dependency for exact replayability — four invariants don't earn a library. |
| Matching the tool to the question (2D chart vs 3D surface) | F12 | Energy is read by hovering a lap, so it is recharts SVG on a zero-canvas route; grip over age is a shape you orbit, so it is a vertex-shaded R3F surface — a second canvas would cost the F-28 budget and buy nothing (5.10.2 rows 3-4). |
| Vertex shader (GPU per-vertex program) | F12 | A small GLSL program run once per grid vertex in parallel that positions it; the tyre surface lifts each vertex to grip = 1 − a·age^b, with fitted a/b passed as uniforms and grip handed to the fragment stage as a varying. |
| Shader ↔ pure-TS twin | F12 | The shader can't run under jsdom, so its equation lives in a testable TS twin (lib/gripSurface.ts) the tests pin, and the GLSL mirrors it; they are forced to agree at the fitted 30 C slice, the only slice a readout may use (E-09). |
| F-02: usable SOC window, not a per-lap deploy cap | F12 | The 4 MJ is the battery's max−min SOC window (FIA Art 5.4.9 / C5.2.9, verified AR-04), not a deploy limit; per-lap deploy exceeds it because the car harvests mid-lap, so the bars panel draws only the harvest cap and a reference-line list keeps the removed deploy plane out (R-03). |
| Render the fit, not the raw data (E-09) | F12 | The tyre view fetches no telemetry — it draws the fitted power law with its confidence flag, and a provenance-ring test proves no /frames or /energy call fires; a stylised, labelled temperature axis stands in for the term the age-only fit lacks (T5). |
| One rule, two callers (cliff_age_laps) | F12 | The tyre-failure cliff is one function in scenario.py that both the env and the /tyres endpoint call, so the view draws the exact boundary race_env.py enforces rather than a literal of its own. |
| WebSocket client lifecycle vs REST | F13 | A long-lived connection with open/message/close stages, unlike one-shot fetches: resync on open (seek past the buffer, restore tempo — resume itself is a seek, since only ws.py's seek branch clears paused), retry on close with capped backoff (500 ms doubling to 8 s), and treat 4404/4500 as terminal. |
| The E-16 client buffer and idempotent insertFrame | F13 | Every streamed frame lands in one sorted buffer that scrub replays verbatim — never a refetch — and a duplicate lap returns the same array reference, absorbing the one frame every reconnect seek is guaranteed to double-deliver at zero re-renders. |
| StrictMode double effects and ref guards | F13 | React 18's dev StrictMode runs each effect setup-cleanup-setup on mount to expose unsafe side effects; a useRef flag makes the deep-link POST fire once, and the socket's dispose() is a true inverse so the double mount leaves one socket and no timers. |
| Structural typing (the injectable PlaybackStore) | F13 | TypeScript matches types by shape, not name: ReplayScene accepts any store exposing selector-call plus getState over the PlaybackSlice fields, so the replay store, the live store and View 6's shared-clock panes all plug into one scene component. |
| Scissored viewports and GL clear semantics (drei View) | F13 | Two Views tunnel two scenes into one canvas, each rendered scissor-clipped to its pane's rectangle (F-28 keeps one context, one root camera keeps orbits in lockstep); the scissored path disables autoClear, so each pane must set an explicit background or frames smear. |
| Trace-donor pairing for served pairs | F13 | The pair job records the real-replay episode once and twin-rolls both legs on its EventTrace (donor = the replay side, evals.py's convention), because seed pairing diverges after the first different stop — F06's twin, now serving the F-24 comparison. |
| Purpose-namespaced cache keys (E-15 extended) | F13 | A purpose discriminator folded into the E-15 key's scenario digest, so a twin-rolled counterfactual leg never answers a plain /simulations POST for the same scenario and seed, and a plain run never dedupes a pair down to one leg. |
| Percentile bootstrap confidence interval (A-06) | F14 | Resample the observed races with replacement 10,000 times and take the 2.5/97.5 percentiles of the resampled means; the point estimate stays the real sample's mean, so the seed moves the interval and never the answer. |
| Exact paired sign test and the pre-registered bar | F14 | Binomial test on the signs of paired deltas with ties dropped from the denominator; M2's 9-of-10 bar at alpha 0.05 is written into `configs/eval.yaml` before the first roll, because a test chosen after the result is a test chosen to pass. |
| Precision and recall as an inseparable pair (E-03) | F14 | Recall alone is free — always-pit never misses an opportunity — so M5 reports both, separately for SC and VSC, with its denominator published. |
| Decision-timing rule (informed decision lap) | F14 | The action for lap L is chosen against the mask built at the end of lap L−1, so a stop on a neutralisation's onset lap was decided blind and is excluded from M5's denominator; pit-entry legality reads `trace.wetness[L-2]` for the same reason (E-08). |
| Afterstate branching and SplicedPolicy | F14 | Replay a fixed prefix of the realised actions, change one decision, then hand the race back to the agent's own policy; the alternative keeps racing without being re-optimised with hindsight, which would be M3's question rather than M5's. |
