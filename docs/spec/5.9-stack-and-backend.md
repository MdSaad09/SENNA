## 5.9.1 Pinned stack — pin what breaks, float what does not

| Layer | Package | Pin | Why this pin |

| Runtime | Python | 3.11.x | Stable target for SB3 / FastF1 / SHAP together |
| Data | fastf1 | >=3.7,<4 | 3.7 is the Jolpica-backed line (F-10); major-pin against breaking changes |
| Data | pandas / numpy | >=2.2 / >=1.26 | FastF1 3.7 compatibility floor |
| RL | gymnasium | match SB3 pair | Version driven by the SB3 release used |
| RL | stable-baselines3 + sb3-contrib | same minor, e.g. 2.6.* | MaskablePPO lives in contrib; the pair must match minor-for-minor. Verify the exact latest pair at Phase 0 and freeze in the lockfile |
| RL | torch | >=2.2,<3 (CPU build fine) | Policy is tiny; CPU wheels simplify deployment images |
| XAI | shap / xgboost | >=0.45 / >=2.0 | TreeSHAP path of Section 5.8 |
| Backend | fastapi / uvicorn / pydantic | >=0.111 / latest / 2.x | v2 choices kept |
| Backend | SQLAlchemy / alembic / asyncpg | 2.0 / 1.13 / 0.29 | v2 choices kept |
| Backend | redis client / rq | 5.x / 1.16 | RQ is the simplest adequate job queue (F-26); Celery is overkill for one worker |
| Tracking | wandb | 0.17+ | Kept from v2 |
| Frontend | react + react-dom | 18.3 (NOT 19) | R3F 8 pairs with React 18; R3F 9 requires React 19 — mixing them is the most common R3F install failure |
| Frontend | @react-three/fiber / drei / three | ^8.17 / ^9.x / 0.16x exact pin | The triad must be mutually compatible; pin three exactly because drei helpers track specific three versions |
| Frontend | vite / tailwind / zustand / react-query / recharts / d3 | 5 / 3.4 / 4.5 / 5 / 2.12 / 7 | v2 choices kept |
| Infra | postgres / redis images | 16-alpine / 7-alpine | v2 choices kept |

Lockfiles (pip-compile + package-lock.json) are committed in Phase 0; "pinned" means reproducible from the lockfile, not that these floors are the newest possible versions.

## 5.9.3 WebSocket and worker

- WS /ws/simulations/{run_id}. Server events: sim:lap (LapFrame + DecisionCard), sim:event (SC/VSC/red/weather/pit), sim:complete (summary). Client events: client:speed {1|5|10|30}, client:pause, client:seek {lap}.
- The worker (RQ) runs the whole race immediately, persists every LapFrame and DecisionCard to Postgres, and publishes to Redis. The API streams to browsers on a playback clock reading the stored frames (E-16) — reconnection and scrubbing are therefore trivial, which keeps v2's "never lose a race to a dropped connection" requirement.
- Redis keys: cache sim:{model_version}:{env_hash}:{seed} (E-15); channel events:{run_id}; queue default RQ.
