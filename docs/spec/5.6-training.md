# 5.6 Training pipeline — MaskablePPO

Extracted from the SENNA Master Implementation Specification v3.0 (7 July 2026) — docs/spec/source/SENNA_Master_Spec_v3.pdf, Part 5. The PDF is the authority; report divergences, never patch them here.

## 5.6.1 Hyperparameters (default · range · reasoning)

| Parameter | Default | Range | Reasoning |
|---|---|---|---|
| Algorithm | MaskablePPO (sb3-contrib) | — | PPO stability on long horizons plus native MultiDiscrete action masking; the masking is the compliance architecture (F-16) |
| Network | MLP pi=[256,256], vf=[256,256] | [128,128] to [512,256] | 32-dim input needs no more; a small policy keeps surrogate distillation faithful (5.8) |
| n_envs | 12 (SubprocVecEnv) | 8–16 | One per physical CPU core; the env is pure Python + NumPy, so CPU parallelism is the throughput lever, not the GPU |
| n_steps | 512 per env | 256–1024 | Rollout of 6144 steps spans roughly 100 episodes — enough full races per update for stable advantage estimates on a 44–70 step horizon |
| batch_size | 1024 | 512–2048 | Divides the 6144 rollout evenly (6 minibatches) |
| n_epochs | 8 | 4–10 | Standard PPO reuse; watch approx_kl in W&B |
| learning rate | 3e-4, linear to 0 | 1e-4 to 5e-4 | SB3 default region; linear decay replaces v2 cosine — one fewer shape to justify |
| gamma | 0.997 | 0.995–0.999 | v2's argument kept: 0.997^69 = 0.81 preserves lap-1 influence at lap 70; sensitivity run at 0.999 noted |
| gae_lambda | 0.95 | 0.9–0.98 | Standard bias-variance point |
| clip_range | 0.2 | fixed | PPO standard |
| ent_coef | 0.01, linear to 0.002 | — | Explore early, commit late (kept from v2, endpoint raised slightly to avoid premature collapse in Stage C stochasticity) |
| vf_coef / max_grad_norm | 0.5 / 0.5 | fixed | SB3 defaults; no evidence they need touching here |
| VecNormalize | obs=True, reward=False | — | Observations vary in scale; reward is already hand-scaled and a running reward normaliser would shrink the sparse terminal signal. Statistics saved with every checkpoint (F-23) |
| Total budget | 8M steps (A 1.5M / B 2.5M / C 4M ceilings) | extend to 15M if throughput allows | Replaces v2's unpriced 20M (R-12); gates can end stages early |
| Seeds | 3 for headline, 2 per ablation | — | Mean and spread reported; single-seed RL results are noise |

## 5.6.2 Compute reality check (do this before believing any schedule)

Phase-2 exit includes a measured throughput number: steps/second across 12 workers for 100k steps. Expectation for a NumPy lap-level env with 22 cars: roughly 1,000–4,000 steps/s aggregate, putting 8M steps at 0.5–2.5 hours — training is then cheap and the 3-seed and ablation plans are safe. If measured throughput is below ~300 steps/s, profile the env (usual culprits: per-step Python object churn, pandas in the hot loop) before touching the budget. GPU is optional: the policy is tiny; answer OQ-2 anyway for headroom.

## 5.6.3 Ablation set (4 runs + 1 optional, 4M steps and 2 seeds each)

| # | Run | Question it answers |
|---|---|---|
| 1 | No curriculum (Stage C from scratch) | Does staging actually buy sample efficiency or final quality here? |
| 2 | Penalty-based constraints instead of masks (v2's -8 architecture) | Direct test of F-16: quantifies violations during learning and any final-policy gap |
| 3 | v2's 12-term reward vs the v3 3-term reward | Is heavy shaping helpful or harmful? A likely publishable negative result on reward over-engineering |
| 4 | Terminal-only reward (both shaping terms off) | Are the shaping terms earning their place? |
| 5 (opt.) | A2C at matched budget | Algorithm sanity baseline if compute allows; DQN excluded with the documented MultiDiscrete reason (F-18, F-22) |
