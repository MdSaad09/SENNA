# Part 2 — Edge cases and failure modes (with causal mechanisms)

Extracted from the SENNA Master Implementation Specification v3.0 (7 July 2026) — docs/spec/source/SENNA_Master_Spec_v3.pdf, Part 2. The PDF is the authority; report divergences, never patch them here.

v2's edge-case table (Section 9.2) is a genuine strength and is carried forward. The cases below are the non-obvious ones it missed. For each: the mechanism — why it happens and what it silently corrupts — then the required handling. Grouped by layer.

## 2.1 Simulation and regulation edge cases

| ID | Failure mode | Causal mechanism — why it happens and what it hides | Required handling |
|---|---|---|---|
| E-01 | SOC depletion cascade | Deploying more than you harvest for consecutive laps drains the 4 MJ store; once SOC hits the floor the car derates on straights, loses places, falls into dirty air, brakes later behind traffic and harvests less — a self-reinforcing spiral. If the simulator lets SOC go negative or refills it magically, the agent never learns the real cost of aggression and every "energy banking" finding is an artefact. | SOC hard-clipped to [0, 4] MJ; requested deployment above available energy is physically derated with an explicit lap-time penalty term; property test: 100k random action sequences, SOC never leaves bounds, energy conserved to 1e-9 MJ. |
| E-02 | Per-circuit harvest caps that move mid-season | The FIA adjusts the recoverable-energy limit per event (baseline 8.5 MJ; roughly 5-9 MJ range; reduced further in some qualifying sessions). A constant 8.5 in code makes Monza strategy wrong by construction and dates the project the next time the FIA tweaks a value. | H_max is a per-event field in circuits.yaml with a source note and date; the assumptions register tracks it; the env reads config, never a literal. |
| E-03 | VSC treated as SC | A virtual safety car slows everyone by a delta with no bunching; a full SC bunches the field and roughly halves relative pit loss. Collapsing both into one flag (v2 state #16) makes the agent value VSC windows like SC windows — it will pit under VSC when staying out was right, and the "SC exploitation" metric silently mixes two different opportunities. | Separate track states (green / VSC / SC / red) one-hot in the observation; separate pit-loss multipliers fitted from 2022-2026 data; metrics reported per state. |
| E-04 | Red flag = free tyre change | Under red flag, cars may change tyres in the pit lane at zero race-time cost. This single rule can invert an entire strategy (track position becomes king). v2 models red flags but not the free change, so simulated red-flag races diverge wildly from the real races used for validation — and the divergence looks like agent error. | Red-flag handler grants a compound choice to all cars at restart; noted in era config (applies to both eras); validation excludes or era-matches red-flagged real races. |
| E-05 | Mass-pit ordering under SC | When the field pits on the same lap, exit order depends on pit-lane queueing and stationary time variance. Resolving simultaneous stops naively by pre-pit order deletes the very mechanism (double-stacking losses, pit-lane traffic) that makes SC decisions interesting. | Pit lane modelled as a FIFO with per-car service time draws; positions recomputed from cumulative race time, never swapped in place; property test with 22 simultaneous stops. |
| E-06 | Rival archetype degeneracy under SC | If all three scripted archetypes share one "pit under SC" rule, every SC produces the same field response; the agent memorises that pattern, and the 78% "SC exploitation" score measures pattern-matching against your own script — it can collapse against any other opponent behaviour. | Archetype parameters (pit thresholds, SC response probability, pace sigma) drawn per race from documented distributions; a held-out parameter band is reserved for evaluation only (train/test split on opponents), Section 5.12. |
| E-07 | Backmarker traffic after pitting | A pit stop drops the agent into slower traffic; if lapped cars are not modelled as moving obstacles with dirty air, the simulator prices pit stops too cheaply and the agent systematically over-pits — which then looks like "aggressive strategy discovery". | All 22 cars simulated with the same pace/traffic model; overtaking a slower car costs a fitted time penalty scaled by pace delta and override availability. |
| E-08 | Wet-transition cliff timing | Crossover between slicks/inters/wets is a threshold on continuous wetness; if wetness updates once per lap while the threshold sits mid-lap, the optimal switch lap is ambiguous by one lap — exactly the margin the British GP counterfactual is meant to test. | Wetness integrates sub-lap (3 sectors); compound validity evaluated at pit-entry time; the ambiguity is stated in the counterfactual write-up. |

## 2.2 Data pipeline edge cases

| ID | Failure mode | Causal mechanism | Required handling |
|---|---|---|---|
| E-09 | In/out laps poison tyre fits | PitIn/PitOut laps carry NaT or inflated LapTime; if they enter the degradation regression, every stint appears to end with a cliff, and the fitted "thermal runaway" is partly a data-cleaning bug wearing a physics costume. | Exclude in/out laps and IsAccurate==False laps from fits; report per-fit counts of excluded rows in the data-quality report. |
| E-10 | Track evolution vs fuel burn identifiability | Lap times fall through a race because fuel burns off AND the track rubbers in. Fitting either alone absorbs the other's effect; v2 fixes fuel at 0.035 s/kg and evolution at -0.04 s/lap independently, which double-counts the trend and biases tyre degradation the other way. | Joint fit per race: lap_time ~ tyre(age,compound) + a*fuel_mass + b*lap_number with compound fixed effects; report collinearity; carry the fitted a, b into the simulator. |
| E-11 | Sprint weekends break session assumptions | Sprint formats change session names/order and give fewer representative race laps; ingestion code that assumes FP1-FP2-FP3-Q-R crashes or mislabels, and per-circuit models quietly train on half the expected data. | Ingest by session type from the event schedule API, not by fixed name list; per-event row counts asserted in the quality report. |
| E-12 | Jolpica / OpenF1 rate limits during bulk ingest | Jolpica is a free community service with request budgets; OpenF1 free tier allows about 3 req/s. A naive per-lap loop across ~70 weekends trips 429s mid-ingest and leaves a partially-written database that later reads as "2023 had fewer pit stops". | One-shot bulk ingest with FastF1 on-disk cache, client-side throttling, resumable checkpoints per event, and a completeness assertion (expected vs loaded events) before any modelling. |
| E-13 | Madrid 2026 has no data until September | A brand-new street circuit joins the calendar in September 2026; any "all circuits" claim or hard-coded list breaks, and the ribbon pipeline has no GPS source for it until FP1. | Circuit library is generated from ingested data (F-08); Madrid auto-appears after its first session; claims phrased as counts computed at build time. |
| E-14 | 2026 rounds as both calibration and test set | Using all available 2026 races to tune the synthetic generator and then "validating" on the same races is train-test contamination — the validation chapter would be circular. | Freeze the split now: rounds 1-6 calibrate, later rounds (and all future rounds as they happen) are held-out test. The split date is recorded in the repo. |

## 2.3 Serving and frontend edge cases

| ID | Failure mode | Causal mechanism | Required handling |
|---|---|---|---|
| E-15 | Redis cache serving a stale model's results | Completed simulations are cached; after retraining, identical request bodies hit the old cache and the demo shows decisions the new model would not make — an explainability nightmare, since the SHAP panel then "explains" a ghost. | Cache keys include model_version and env_config_hash; deploying a model bumps the version and cold-starts its own namespace; TTL 7 days as backstop. |
| E-16 | WebSocket consumer slower than producer | The worker can simulate 70 laps in under a second; pushing events at production speed floods the socket and the browser animation timeline. Naive sleeps in the worker then couple simulation speed to playback speed. | Worker publishes the complete lap log to Redis/Postgres immediately; the API streams to clients on a playback clock (1x/5x/10x/30x) from the stored log — pause/scrub/reconnect all read the same source of truth. v2's reconnect requirement is kept. |
| E-17 | Ribbon self-intersection at hairpins | Extruding a 12 m ribbon along a curve whose radius is under 6 m makes inner edges cross; Frenet frames also flip at inflection points, twisting the mesh. Monaco and Hungary produce visibly broken geometry precisely on the corners recruiters zoom into. | Rotation-minimizing frames; clamp effective half-width to local radius; geometry unit test asserts no self-intersection across all circuits (E-17 test in Section 5.10). |
| E-18 | GPU context loss on mobile / long sessions | Browsers reclaim WebGL contexts under memory pressure; a black canvas mid-demo with no handler looks like a crash. | Listen for webglcontextlost / restored; show a reload overlay; keep one canvas per route (F-28) to minimise pressure. |
