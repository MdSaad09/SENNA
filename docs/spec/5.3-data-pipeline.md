# 5.3 Data pipeline — exact sources, columns and cleaning contract

Extracted from the SENNA Master Implementation Specification v3.0 (7 July 2026) — docs/spec/source/SENNA_Master_Spec_v3.pdf, Part 5. The PDF is the authority; report divergences, never patch them here.

## 5.3.1 Sources and versions

| Source | Pinned | Covers | Used for | Limits to respect |
|---|---|---|---|---|
| FastF1 (Jolpica backend) | fastf1>=3.7,<4 | 2022-2026 sessions: laps, car/pos telemetry, weather, race control, results, schedules; circuit corner info | Everything: physics fits, replays, ribbons, results | Enable on-disk cache before any call; bulk ingest once; Jolpica request budget respected via cache |
| OpenF1 REST | HTTP v1 | 2023-2026: pit durations, stints, intervals, positions, race control, weather | Pit-loss distributions per circuit; interval cross-checks | Free tier ~3 req/s; historical only (real-time is paid); no 2022 |
| Real 2026 rounds | via both above | Rounds raced so far (~10 by 7 July) | Calibration (rounds 1-6) and held-out validation (rounds 7+) | Split frozen now (E-14) |

## 5.3.2 FastF1 objects and the columns actually consumed

| Call | Columns consumed | Feeds |
|---|---|---|
| fastf1.get_event_schedule(year) | RoundNumber, EventName, EventFormat, Session dates | Ingest plan; sprint handling (E-11) |
| session.laps | Driver, DriverNumber, Team, LapNumber, LapTime, Stint, Compound, TyreLife, FreshTyre, PitInTime, PitOutTime, Sector1/2/3Time, SpeedST, Position, TrackStatus, IsAccurate, LapStartTime | Tyre degradation fits; pit timing baselines; position traces; track-status timeline |
| lap.get_car_data() | Speed, Throttle, Brake, nGear, RPM, DRS at roughly 4-5 Hz (about 240 ms) — not 10 Hz as v2 stated | Braking-energy integrals; full-throttle fraction for deployable-energy estimates |
| lap.get_pos_data() | X, Y, Z (decimetres), Status | Circuit ribbon centreline (F-12); replay splines |
| session.weather_data | AirTemp, TrackTemp, Humidity, Rainfall, WindSpeed (per minute) | Weather state machine; temperature modifiers |
| session.race_control_messages | Category, Flag, Status, Message, Lap | SC/VSC/red timelines; per-circuit event rates |
| session.results | Abbreviation, TeamName, GridPosition, Position, Status, Points | Baselines; counterfactual ground truth; rival pace priors |
| fastf1.get_circuit_info() | corners (Number, Distance, X, Y, Angle), rotation | Corner annotations draped on the ribbon (not the centreline itself) |

## 5.3.3 OpenF1 endpoints (historical only)

| Endpoint | Key params | Fields consumed | Feeds |
|---|---|---|---|
| /v1/sessions | year, session_name | session_key, meeting_key | Key mapping for all other calls |
| /v1/pit | session_key | pit_duration, lap_number, driver_number | Pit-lane loss distribution per circuit (mean + sigma for the FIFO model, E-05) |
| /v1/stints | session_key | compound, lap_start, lap_end, tyre_age_at_start | Cross-check of FastF1 stints; 2026 compound behaviour |
| /v1/intervals | session_key | gap_to_leader, interval | Gap dynamics sanity checks |
| /v1/race_control | session_key | category, flag, message | SC/VSC ground truth cross-check |
| /v1/weather | meeting_key | air/track temperature, rainfall | Weather calibration 2023+ |

## 5.3.4 Cleaning contract (applied before any model fit)

- Drop laps with IsAccurate == False; drop in-laps and out-laps (PitInTime or PitOutTime set) from pace and degradation fits — they remain in the pit-timing dataset.
- Parse TrackStatus digit strings; a lap is "green" only if the whole lap is status 1; SC/VSC laps are excluded from pace fits and included in the event-rate fits.
- LapTime NaT: never impute for fits; impute only for replay display, flagged in the row.
- Telemetry gaps over 2 s: split the trace; never interpolate through a gap for energy integrals.
- Position data: convert decimetres to metres; drop points with Status != "OnTrack"; per-session z-score outlier gate on point-to-point speed.
- Wet or red-flagged races are excluded from dry tyre fits and analysed separately.
- Per season, emit data_quality_report.md: events expected vs loaded, rows kept vs dropped per rule, channels missing per session. Modelling may not start until the report exists (F-14).

## 5.3.5 Storage

The v2 schema (Section 8.3) is kept with these changes: laps gains energy_deployed_mj, energy_harvested_mj, soc_end_mj (simulated rows only) and an era + source flag (real_2022 ... real_2026 / synthetic_2026); agent_decisions stores one JSONB per decision (state, masks with reasons, action, probs, shap top-k) rather than one row per feature; simulation_runs gains env_config_hash and model_version (E-15).
