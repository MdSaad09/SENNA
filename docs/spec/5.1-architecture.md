## 5.1 System architecture

```
DATA LAYER                    LEARNING LAYER                 SERVING LAYER
-----------                   ---------------                --------------
FastF1 >=3.7 (Jolpica) --+                                   FastAPI api
OpenF1 (2023+, hist.) --+|--> PostgreSQL <---- eval logs <-- (REST + WebSocket)
Real 2026 rounds -------+|         |                              |     ^
                          |        v                              v     |
                          |   physics fits ---> F1RaceEnv     RQ worker |
                          |   (yaml configs)    (Gymnasium)   (frozen   |
                          |        |                |          model)   |
                          +--> synthetic 2026       v              \    |
                               generator       MaskablePPO          Redis
                                               + curriculum       (queue +
                                                    |             pub/sub +
                                                    v              cache)
                                            model artifact           |
                                            + vecnorm stats          v
                                            + SHAP surrogate    React 18 + R3F 8
                                                                 six 3D views
```

Three invariants: (1) training never happens in the serving layer; (2) every number the frontend displays is fetched from the API, which reads Postgres — no client-side physics; (3) every model artifact ships as a triplet: policy weights + VecNormalize statistics + SHAP surrogate, versioned together.
