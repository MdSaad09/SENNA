# F17 plan — Driver identity

Approved by Saad, 9 August 2026, with both proposed defaults taken.
Spec: `docs/spec/features/F17-driver-identity.md`.

> F17 extends master spec v3.0 rather than implementing a row of it. Its spec anchors are
> contracts it must not break, not rows it delivers.

## Objective & spec anchors

Replace the anonymous per-car pace draw with named drivers whose numbers come from the
data. `joint_pace.py:102` already fits a per-driver fixed effect; `:114` folds the vector
into `t0_s` via its mean and `:122` keeps only its standard deviation, which becomes the
`sigma_driver_s` the env draws from. F17 persists the effects instead of summarising them.

The sharpest justification is written in the code already. `senna/eval/traces.py:13` says
*"Driver pace offsets are drawn, not fitted, because per-driver skill is deliberately not
modelled"*, and `:94` calls `rng.normal` while the same function holds `laps_by_driver`
keyed by real driver codes. M2's counterfactual harness knows which seat is Verstappen's
and gives it a coin flip.

Anchors, as invariants:

- **E-10** — driver effects come out of the joint regression, so its identification discipline applies unchanged: the VIF gate, and `_refuse_validation_rounds` keeping the fit off held-out 2026 rounds (E-14).
- **T5** — `deg_mult` scales the fitted amplitude `a`. The power law's form does not change; `tyre_deg_s` and `grip_est` keep their signatures.
- **5.5.3** — one multiplication enters `lap_time_s`. No new term.
- **M1** — `rivals.py:8-9` records that archetypes deliberately carry no pace offset, because tying strategy style to car pace confounds the paired-baseline metric. Driver identity threatens exactly that.
- **M2** — the feature's point.
- **M11** — luck share (0.758 in F14) is measured against pace dispersion, so its *interpretation* shifts once dispersion is named rather than drawn. Flagged in the ship report; not renegotiated here.

**The correctness detail exploration turned up.** The design matrix uses drop-one coding
(`joint_pace.py:197`), so driver effects are relative to a dropped baseline driver, and
`t0_s` at `:114` already absorbs `driver_effects.mean()`. Persisting the raw effects and
assigning them to `driver_s` would shift every lap time by that mean. **The effects must
be centred** — `effect[d] - mean(effects)` — so `t0_s` keeps its current meaning. The
happy consequence: centred effects have standard deviation equal to `sigma_driver_s` by
construction (`:122`), so a named lineup and the random draw are distributionally matched.
That is what keeps M1 from moving.

## Deliverables

- **`senna/physics/fits/joint_pace.py`** — `JointPaceFit` gains `driver_effects_s: dict[str, float]`, centred. `_effects` returns a bare array today and discards the level names; it must return them paired. `sigma_driver_s` stays for the fallback.
- **`senna/physics/fits/tyre_style.py`** — new. Per-driver multiplier on the pooled degradation amplitude, from an `age x driver` interaction on F02's partial residuals, with an identification gate mirroring `degradation.py:59-64`. Returns `(mult, identified)` per driver.
- **`senna/physics/fits/run.py`** — build the driver tree and write `configs/drivers.yaml` **through the existing `params_writer`**, not a new emitter. Every leaf is a `(value, origin)` pair exactly as `physics_params.yaml` already is; `render_params` already takes a `header=` argument.
- **`senna/physics/fits/params_writer.py`** — add `validate_origins(params)` beside `validate_complete`: refuse a leaf whose origin string is empty or carries no recognised tag. Ten lines, and it upgrades the interpretability contract from convention to gate for both files.
- **`senna/env/scenario.py`** — `build_scenario(circuit, era, *, drivers=None)`; `CircuitScenario` gains `driver_pace_s` and `driver_deg_mult`, both `None` without a lineup.
- **`senna/env/race_env.py`** — `F1RaceEnv(..., drivers=None)`. With a lineup, `driver_s` is read from the table; without, today's draw is untouched.
- **`senna/env/dynamics.py`** — `lap_time_s` takes a per-car `deg_mult` array defaulting to ones; one multiplication against `a`.
- **`senna/eval/traces.py`** — fill `driver_s` from the table via `laps_by_driver` keys, and rewrite the docstring paragraph that currently apologises.
- **`notebooks/fit_driver_identity.ipynb`** — residual plots and the identification table.
- **`configs/fits.yaml`** — the new gate, beside the existing `min_drivers: 2`.

## Constants & configs

Everything lands in `configs/drivers.yaml`, generated by `make fit`, never hand-edited.

| Name | Value | Origin | Home |
|---|---|---|---|
| `drivers.<CODE>.pace_s.<circuit>` | fitted | **fitted** — `notebooks/fit_driver_identity.ipynb` | `configs/drivers.yaml` |
| `drivers.<CODE>.deg_mult` | fitted where identified, else `1.0` | **fitted** / **stylised** with `identified: false` | `configs/drivers.yaml` |
| `drivers.<CODE>.n_laps`, `.n_stints` | fitted | **fitted** — the sample behind each claim | `configs/drivers.yaml` |
| `min_stints_for_deg_mult` | **6** — two stints per compound across three compounds, the smallest sample that can separate a driver's amplitude from stint-to-stint noise; sized in the notebook | **stylised**, matching how `min_stints: 3` is already tagged | `configs/fits.yaml` |

`sigma_driver_s` stays in `physics_params.yaml` untouched — it is still what an unnamed
grid draws from, and removing it would break the default path.

## Tests first

- **`test_the_default_grid_is_byte_identical`** — F16's golden fixtures replay exactly with `drivers=None`. Inherited wholesale; this is the gate that keeps F14 and the frozen model safe, and it costs nothing.
- **`test_driver_effects_are_centred`** — the persisted effects sum to zero across the fitted lineup, and their standard deviation equals the same fit's `sigma_driver_s`. The test for the drop-one bug above; without it a constant pace shift passes silently.
- **`test_a_named_lineup_seeds_the_fitted_offsets`** — `state.driver_s` equals the table in seat order, and no driver-pace normal is drawn.
- **`test_an_unnamed_seat_falls_back_to_the_draw`** — a short lineup, or a code absent from the table, fills remaining seats from `N(0, sigma_driver_s)`. Not zero: zero would quietly make an unknown driver the best on the grid.
- **`test_a_faster_driver_finishes_ahead_on_equal_strategy`** — two seats, identical decisions every lap, differing only in `pace_s`. The end-to-end statement that identity reaches the result.
- **`test_tyre_management_lengthens_the_useful_stint`** — *property test.* Lap-time delta at a given age is monotone in `deg_mult` over a bounded range. Direction, not magnitude.
- **`test_archetype_assignment_is_independent_of_driver_identity`** — *property test.* Over many seeds, archetypes assigned to a given code are uniform. The M1 guard, and the test least obvious to a reader in six months.
- **`test_real_race_traces_carry_the_real_driver`** — `trace_from_real_race` with VER/HAM/LEC keys produces matching `driver_s`.
- **`test_every_driver_constant_declares_its_origin`** — `validate_origins` over the built tree; a leaf without a recognised tag raises. Structural, not comment-parsing.
- **`test_deg_multiplier_falls_back_when_unidentified`** — below the gate, `1.0` and `identified: false`, never a noisy fitted value.
- **`test_drivers_yaml_renders_byte_deterministically`** — matching `params_writer`'s existing guarantee that a `make fit` rerun leaves `git diff` empty.

## Edge cases handled

- **E-10 / E-14** — effects come from the gated regression; `_refuse_validation_rounds` stays in the path, so nothing is fitted on held-out 2026 rounds.
- **T5** — multiplier on `a`; form unchanged.
- **A-05** — `EventTrace` needs **no schema change**: it already carries `driver_s`, so a named lineup puts different values in an existing field. Saved traces under `models/*/stage_b_traces/` keep loading.
- **E-06** — the archetype draw stays independent of the driver table, by construction and by property test.
- **Solo (F07 Stage A)** — a one-car grid takes its named driver's pace, or today's draw.
- **Three-level pace fallback** — per-circuit fitted where available; that driver's mean across fitted circuits where the circuit is missing; the random draw where the driver is unknown entirely. Each level recorded in the config so a reader can tell which applied.

## Out of scope

- **Aggressive overtaking** — there is no on-track pass event in the engine; classification is cumulative race time, and T7's `P(pass)` lives in `senna/physics/synth/overtaking.py`, which `senna/env` never imports. Giving a driver better overtaking means first giving the engine overtaking, which changes every race.
- **Late braking** — no braking term in 5.5.3 to attach it to.
- **Per-driver degradation curves** — `degradation.py:61` refuses thin data for a real reason. F17 fits a multiplier on the pooled curve, which is estimable.
- **Retuning M11** — luck share is measured against pace dispersion, so its reading changes when dispersion becomes named. Flagged in the ship report, not renegotiated here.
- Teams and teammates (F22), physics uncertainty (F18), any observation change (F20).

## Decisions (Saad, 9 August 2026)

**1. No default 2026 lineup.** A named 2026 grid means asserting who drives for Cadillac
next season — a fabricated claim wearing a fitted file's authority, which the calibration
data cannot support. `drivers=None` stays the random draw and remains what training and
F14 use; named lineups are opt-in, and `eval/traces.py` takes its lineup from the ingested
data rather than a guess. "Verstappen at Bahrain" then means a real 2024 race with the
real grid, which is the stronger claim anyway.

**2. The wet multiplier is dropped.** The spec originally listed it. There is not enough
per-driver wet running in the calibration split to fit one, so it would have shipped
`stylised` — an invented number about a named real person, in the file whose entire
purpose is answering "how do you know that?". Two honest parameters beat three with one
fabricated. It returns when data supports it, or not at all.

## Notes for the build

**The RNG hazard is the same one F16 taught.** `driver_s = self._rng.normal(0.0,
sigma_driver_s, n)` sits in `reset()` between the grid permutation and the rival field
draw. Delete that call and every seeded race in the repo changes — the frozen model's
evaluation, the Stage B traces, F14. The `drivers=None` default must consume the stream
exactly as it does today; a named lineup is a different mode and may legitimately shift
it, in the same way `weather="dry"` already skips the weather roll. F16's golden fixtures
prove the default path did not move, and they cost nothing to reuse.

**Centre the effects before persisting them.** See the objective. This is the one change
that is silently wrong rather than loudly wrong.

**Reuse `params_writer`, do not write a second emitter.** Every leaf of
`physics_params.yaml` is a `(value, origin)` pair rendered with its origin as a trailing
comment, sorted and byte-deterministic. `drivers.yaml` is the same shape with a different
header. This also makes the provenance test structural rather than a comment parser,
which is why `validate_origins` belongs in this feature rather than a later one.

**Fit the tyre multiplier honestly or label it.** The estimable quantity is a per-driver
multiplicative factor on the pooled amplitude. Where a driver has too few stints, report
1.0 and mark it unidentified — do not let a noisy coefficient into `drivers.yaml` wearing
a `fitted` tag.

**This feature's risk is provenance, not physics.** The code is small: one multiplication
in `lap_time_s`, one lookup in `reset`, one dict persisted instead of averaged. What is
large is a config file of per-driver numbers an examiner will read as claims about real
people. Every one needs to survive "how do you know that?", and the honest answers include
"I don't, so it is 1.0".
